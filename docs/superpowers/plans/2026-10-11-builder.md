# Builder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A builder that reads one brief and one tool API file and creates a Freya phone agent that passes unseen cases, plus the evaluation loop that proves it improves and generalizes.

**Architecture:** `builder/build.py` is a deterministic shell around a Claude Agent SDK run. The agent follows one skill: it writes a rule ledger and a values file, then a per-brief generator script that uses our tested block library, then runs the loop-1 checks and deploys only through a gate. `eval/` builds a suite of dev and held-out briefs and scores them with the kit's `run_cases.py`.

**Tech Stack:** Python 3.12 (`.venv`), `claude-agent-sdk` 0.2.165, `pytest`, the kit's `freya.py` and `tools/run_cases.py` (standard library only).

**Spec:** `docs/superpowers/specs/2026-10-11-builder-design.md`

## Global Constraints

- Run command: `python3 builder/build.py {brief_path} {tool_api_path}`. Locally: `.venv/bin/python builder/build.py ...`.
- Build time: target 20 minutes, watchdog at 27 minutes, hard limit 30 minutes.
- Builder model: `claude-opus-5-5`, overridable with `BUILDER_MODEL`.
- Phone-agent model: `AGENT_LLM` from `kit/freya.py`. Never change it.
- No value, rule or name from any brief (public, variant or hidden) in `builder/`. Test fixtures use the year 2031 and neutral names.
- `builder/` imports `kit/freya.py` (add `kit/` to `sys.path`). Never copy it. Never write into `context/`.
- Every workflow save goes through the gate in `builder/blocks/deploy.py`. One workflow per slot, updated in place. Slot = brief file stem. State file: `<repo>/.freya-agents.json`.
- Workflow JSON: no `null`; booleans tested as `"true"` and `"True"`; mapping paths start with `data.`; code contains no `{{` or `}}`; every passthrough ends with an `always` transition.
- Commit messages: plain English, no AI attribution (user rule).
- Before any builder run in `kit/`, move `kit/results/` out to `runs/` (baseline rule). The builder's own runs write under `builder/runs/` (git-ignored).

## Review Focus

1. A tool API file with renamed fields, new enum values, an object or array field, or no `servers` entry: `make_tool` must build a valid tool or raise a clear error, never emit a broken tool. (Test in Task 4.)
2. The agent run crashes, times out, or never writes `workflow.json`: `build.py` must still end with an export of the last deployed version, or exit non-zero with the reason in the trace. (Test in Task 9.)
3. `now` on a weekend, on a holiday, on the last day of a year: date helpers must return correct business days. (Tests in Task 2.)
4. An API key inside an exception message or a tool result: the trace must redact it. (Test in Task 9.)
5. A raw-material brief where a memo replaces an earlier rule: the ledger must hold only the new rule and name both sources. (Covered by the skill text in Task 10 and the V1 brief in Task 12; checked by `ledger_problems` refusing duplicate rule ids in Task 6.)

4. If `run_dir/workflow.json` exists and its hash differs from `run_dir/deployed.json`, call `deploy`. On `GateError`, trace the problems and keep the deployed version.

6. `freya.export_workflow(workflow_id, submission/<slot>.workflow.json)`; trace `created` with workflow id, agent id, node count, tool count, export path; trace `end` with the total seconds; return 0.
